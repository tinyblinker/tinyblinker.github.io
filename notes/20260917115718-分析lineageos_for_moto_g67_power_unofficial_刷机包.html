4. 三,侧载(adb sideload)时的写入机制

  • 全部 14 个分区均会被覆盖写入(全量 OTA,非增量包).
  • 静态分区 (boot/dtbo/init_boot/recovery/vendor_boot/vbmeta/vbmeta_system/pvmfw):
    各自拥有独立物理分区,直接写入 inactive slot.
  • 动态分区 (system/system_ext/product/vendor/system_dlkm/vendor_dlkm):
    写入 super 分区中的 inactive slot,通过 Virtual A/B 快照/COW 机制完成,
    刷机过程中 active slot 与用户数据不受影响,重启后才切换槽位.
  • manifest 标记 system 与 vendor 分区 run_postinstall = true,
    侧载末尾会执行 postinstall 脚本(用于 APEX 激活,dex 优化等收尾工作).

6. 五,防回滚保护(Anti-Rollback)分析

6.1. 机制说明

Android 的防回滚保护基于 AVB (Android Verified Boot) rollback index,
而不是逐分区独立实现,理解上要分两条校验链:

  • system 校验链 (由 vbmeta 统领):涵盖 boot,system,vendor,
    system_ext,product,system_dlkm,vendor_dlkm,dtbo,init_boot,
    vendor_boot 等,这些分区的哈希/hashtree 描述符被打包进 vbmeta 的
    descriptor 中,由 vbmeta 的单一 rollback_index 统一保护.
    也就是说,只要 vbmeta 校验通过且其 rollback_index ≥ 设备当前
    fused/存储的最小值,这一整条链上的分区就被视为合法,不存在"某个
    分区单独有防回滚,另一个没有"的情况.
  • system 子链 (由 vbmeta_system 统领,若设备启用了 chained
    partition):可对 system 相关镜像做独立的次级签名与 rollback_index,
    但本包中 vbmeta_system 仅 4 KiB,通常只是一个占位/链式引用,
    实际保护仍归并到主 vbmeta 的 rollback_index.
  • recovery:在 A/B 无缝升级设备上通常合并进 boot/init_boot 链,
    不单独设防回滚索引;本包仍附带独立 recovery.img,多为兼容/救砖用途.
  • pvmfw:属于 pKVM/AVF 固件,有自己独立的签名验证机制(非标准 vbmeta
    descriptor 链的一部分),部分设备会有单独的 anti-rollback 存储位.
  • dtbo:在支持的设备上可被纳入 vbmeta 的 hash descriptor 一并保护,
    具体取决于厂商 fstab / avb 配置.

简言之:*真正会触发"防回滚"拒绝刷入的不是单个分区各自的版本号,
而是 vbmeta(以及可能存在的 vbmeta_system)里记录的 rollback_index
是否小于设备 tamper-resistant storage(如 fuse/rpmb)中已记录的最小值.*

7. 六,各分区作用详细说明

  • boot:容纳 Linux 内核镜像与通用 ramdisk(GKI 架构下与设备无关),
    是启动流程第一阶段加载的核心镜像.
  • dtbo (Device Tree Overlay):在基础设备树上叠加硬件差异化配置
    (如主板版本,外设差异),使同一内核适配多种硬件变体.
  • init_boot:Android 13 起从 boot 中拆分出来的 init ramdisk,
    专门承载设备无关的第一阶段 init 逻辑,便于 GKI 内核独立更新.
  • recovery:独立恢复环境镜像,用于 OTA 恢复模式,出厂重置,
    以及部分设备的救砖/工程操作入口.
  • vendor_boot:与 boot 配套的厂商专属 ramdisk,承载第二阶段
    init 与厂商特有的启动逻辑,实现"通用内核 + 厂商定制"解耦.
  • vbmeta:AVB 顶层元数据镜像,记录各被保护分区的哈希/哈希树
    描述符与统一的 rollback_index,是整条验证启动链的信任根之一.
  • vbmeta_system:面向 system 相关链的次级 AVB 元数据(chained
    partition),可独立于主 vbmeta 进行签名与版本管理.
  • pvmfw (Protected VM Firmware):Android Virtualization Framework
    (AVF) / pKVM 微虚拟机的固件镜像,用于启动隔离的受保护虚拟机环境.
  • system:Android 框架层核心,包含 system server,Zygote,
    框架 Java/Native 库等系统运行时(erofs 只读文件系统).
  • system_ext:从 system 中拆分出的系统级扩展分区,用于 OEM/GSI
    兼容场景下承载厂商系统服务,避免污染纯净 system 镜像.
  • product:产品差异化层,容纳预装 App,区域/运营商定制内容,
    部分厂商增值服务,便于同一系统镜像适配不同产品线.
  • vendor:HAL(硬件抽象层)实现,厂商专有闭源库,驱动配套的
    用户态组件,是连接内核驱动与 Android 框架的桥梁.
  • system_dlkm:GKI 架构下与 system 相关,可动态加载的内核模块
    (.ko),使内核模块可独立于 boot 镜像更新.
  • vendor_dlkm:厂商私有的可动态加载内核模块,通常是闭源驱动
    模块,与 vendor 分区配合工作.

9.6. 六,侧载修改小结

  1. adb sideload LineageOS23.2-UNOFFICIAL-PORTOV.zip 会在 recovery 中由
    update_engine 将 payload 应用到 非活跃槽位,一次性改写全部 14 个分区:
    • 8 个静态分区直接覆盖 inactive slot 的独立分区;
    • 6 个动态分区经 Virtual A/B 快照写入 super 分区对应槽位.
  2. 防回滚: vbmeta 与 vbmeta_system 的 Rollback Index 均为 11;
    由于 vbmeta 的 Flags=3 禁用了校验,本构建 bootloader 实际不强制
    dm-verity / 签名验证.
  3. 目录中另有 recovery.img, init_boot.img 为与 payload 内 recovery / init_boot
    一致的独立镜像(供 fastboot 单独刷入); copy-partitions-20220613-signed.zip 为
    首次刷机前同步 A/B 槽位的辅助包; MindTheGapps-16.0.0-arm64-...zip 为独立 GApps 包.
